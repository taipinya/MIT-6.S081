# MIT 6.S081 / xv6 Labs 学习与实现记录

> 一个从“这玩意怎么跑”到“居然全过了”的 MIT 6.S081 xv6 实验仓库。

本仓库用于记录我学习 MIT 6.S081 操作系统课程并完成 xv6 labs 的全过程。  
不同的 **branch 对应不同的 lab**，每个分支中包含对应实验的实现代码、调试过程和学习笔记。

代码均已通过对应实验测试，属于 **满分实现版本**。  
如果你也正在和 xv6、页表、trap、Copy-on-Write、mmap、文件系统、网卡驱动、锁优化等内容激情互殴，希望这个仓库能帮你少踩几个坑。

## 仓库简介

MIT 6.S081 是一门非常经典的操作系统课程，实验基于教学操作系统 xv6 展开。  
这门课的实验覆盖了操作系统中许多核心内容，包括：

- 文件系统与符号链接
- mmap 内存映射文件
- 网卡驱动与网络协议栈

这个仓库不是单纯的“答案仓库”，而是一个完整的学习记录。除了代码之外，我还整理了实验过程中的思路、调试记录、踩坑点和复习笔记，方便后续回顾，也方便正在学习这门课的同学参考。

## 仓库特点

### 1. 每个 Lab 独立分支

本仓库采用分支管理方式组织不同实验。不同的 branch 对应不同的 lab，便于查看单个实验的完整代码与学习记录。

```text
main        仓库主页与说明
util        Lab: utilities
syscall     Lab: system calls
pgtbl       Lab: page tables
traps       Lab: traps
cow         Lab: copy-on-write
thread      Lab: multithreading
net         Lab: network driver
lock        Lab: lock optimization
fs          Lab: file system
mmap        Lab: mmap
```

> 友情提示：切 branch 之前记得保存自己的代码，不然 xv6 没把你绕晕，Git 先给你上一课。

### 2. 满分代码 + 学习笔记

每个实验分支中不仅包含最终实现代码，还尽量保留了对应的学习记录，包括：

- 实验目标
- 任务拆解
- 实现思路
- 关键代码修改点
- 调试过程中遇到的问题
- 常见坑点与解决办法
- 相关操作系统知识点总结

很多时候真正难的并不是“这几行代码怎么写”，而是：

> 为什么要这么写？  
> 为什么我这样写测试就炸了？  
> 为什么 xv6 又沉默了？

所以这个仓库会尽量把这些过程记录下来。

## 仓库结构

每个实验分支的结构大致如下：

```text
xv6-labs-2021/
├── kernel/          xv6 内核代码
├── user/            用户态程序
├── notes/           学习笔记与实验记录
├── Makefile
└── README / report  实验说明或总结
```

其中，`kernel/` 和 `user/` 目录主要是 xv6 的源码与实验修改内容；`notes/` 或相关 markdown 文件用于记录实验过程、问题分析和复习总结。

## 如何查看某个 Lab

克隆仓库：

```bash
git clone <your-repo-url>
cd <your-repo-name>
```

查看所有分支：


切换到指定实验分支，例如 `cow`：


```bash
git switch cow
```

运行测试：

```bash

```

启动 xv6：

```bash
make qemu
```

## 学习建议

如果你正在做这些实验，推荐按下面顺序使用本仓库：

1. 先自己阅读 lab handout。
2. 尽量独立实现一版。
3. 遇到卡点时先看学习笔记，不要一上来就看完整代码。
4. 对比关键实现差异。
5. 重新跑测试并理解失败原因。
6. 最后整理自己的复习笔记。

尤其是以下几个实验，建议多花时间理解：

- `pgtbl`：理解虚拟内存和页表映射
- `traps`：理解用户态与内核态切换
- `cow`：理解页表权限、缺页异常和引用计数
- `lock`：理解并发性能优化
- `fs`：理解 inode、日志、符号链接等文件系统机制
- `mmap`：理解虚拟内存和文件系统的结合

这些内容看起来很硬，但啃下来之后，对操作系统的理解会明显上一个台阶。

## 一些踩坑提醒

做 6.S081 的过程中，我遇到过不少经典问题，例如：

- 忘记释放锁，导致 xv6 原地入定
- 页表权限位少设一个，用户程序当场寄
- 引用计数没处理好，COW 变成 Copy-On-Boom
- 文件系统路径解析递归写错，符号链接开始套娃
- `make qemu` 报错，结果发现是 Makefile 缩进炸了
- 测试偶尔失败，最后发现是并发代码有竞态条件
- 锁优化看起来只是在挪结构体，实际上是在和多核调度互相试探

这些问题在笔记里都有尽量记录。  
毕竟 bug 不会消失，只会转移到下一个没看笔记的人身上。
